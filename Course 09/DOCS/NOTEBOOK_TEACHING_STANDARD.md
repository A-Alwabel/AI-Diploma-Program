# Course 09 Notebook Teaching Standard

## Purpose

This standard defines the minimum teaching structure for student-facing
notebooks in `Course 09`.

The goal is not only to show code, but to make each lesson teachable in class
without the instructor having to invent missing explanations live.

## Required Teaching Blocks

Every student-facing notebook should include these elements where relevant:

1. **Lesson Brief**
   - what the lesson is about
   - where it fits in the RL learning path
   - what students should be able to explain after finishing it

2. **Why This Matters**
   - why the concept is needed
   - what problem it solves
   - what confusion it prevents later

3. **Plain-Language Concept Explanation**
   - define the new RL concept simply
   - explain how it differs from nearby concepts
   - connect it to earlier units when possible

4. **Student Support Pack**
   - key terms
   - quick-check questions
   - common mistakes

5. **Step Guide Before Dense Code**
   - what the next code cell does
   - why it matters
   - what kind of output students should expect

6. **Step-by-Step Code Comments**
   - add comments where weak coders may lose the thread
   - prefer explaining intent over restating syntax

7. **Output Interpretation**
   - explain what plots, tables, or printed values mean
   - state what students should conclude from the result

8. **Mini FAQ or Likely Student Questions**
   - add when a topic repeatedly creates classroom confusion
   - focus on "why", "when", and "how is this different?"

9. **Closing Takeaway**
   - summarize the lesson in plain English
   - connect it to the next lesson

## Course-Specific Rules

- Keep student-facing material in English only.
- Do not expose instructor-only solutions, rubrics, or answer keys in student
  notebooks.
- Prefer the numbered notebook path as the official study route.
- If a concept is only supplemental, label it honestly as supplemental.
- Do not assess terminology before it is explicitly taught in the numbered path.

## Teaching Quality Check

Before considering a notebook classroom-ready, ask:

- Can a student explain what this concept is?
- Can they explain why it is used?
- Can they distinguish it from similar RL ideas?
- Can they read the core code without guessing?
- Can they interpret the main outputs?

If the answer is no, the notebook still needs teaching support.
